BoardFlow — UI/UX Design

Static high-fidelity mockups for a Scrum-oriented project management app. Desktop-first (1280px+), light mode throughout, with the Sprint Board also shown in dark mode. Screens are grouped by priority tier below; the design system tokens and core components are documented first.

Tenant: Nova Labs Project: Mobile App Revamp Nav: sidebar + topbar shell

Assumptions & reasoning

Nav shell is constant
Sidebar (org switcher, projects, settings) + topbar (breadcrumb, search, avatar) repeats on every authenticated screen, per spec — this is the anchor of consistency across the whole app.
One accent, used sparingly
Indigo-blue is reserved for primary actions, active nav/tab states, links, and progress bars — never for decoration. Priority/status get their own semantic hues.
Two-font system
Manrope (medium/bold) for headings and UI labels gives a precise, geometric feel; Public Sans (regular/medium) for body and data-dense text stays highly legible at small sizes.
Tier-1 screens get full states
Sprint Board and Backlog show empty, loading (skeleton), and populated — these are the screens users live in daily, so their edge cases matter most.

Design rationale

Layout. A persistent 240px sidebar (org switcher, projects, settings) plus a 56px topbar (breadcrumb, search, avatar) frames every authenticated screen, so users never lose orientation as they move between backlog, board, and admin views. Content areas favor a single dominant surface — the board's four columns, the backlog's single list — over competing panels.

Color. A near-neutral gray scale carries 95% of the UI; the single indigo accent is reserved for primary buttons, active nav state, links, and progress bars, so it stays meaningful. Priority and status get their own semantic hues (red/orange/gray for priority, green/amber for status) so they scan instantly, independent of the accent.

Hierarchy. Manrope's medium/bold weights mark every heading and interactive label; Public Sans regular carries body and data-dense text (task titles, comments). This two-weight-family split gives clear scanning hierarchy without needing size alone to do the work — useful on dense screens like the board and permission matrix.

States. Sprint Board and Backlog — the screens teams live in daily — get full empty/loading/populated coverage, since their edge cases (no active sprint, first load) are common in real use. Tier 2/3 screens are shown populated only, where the interaction pattern matters more than edge-case handling.

Dark mode. Full tokens are defined for both modes, but only the Sprint Board is rendered dark, as the highest-usage screen and best proof of the palette holding up against long board-viewing sessions.
